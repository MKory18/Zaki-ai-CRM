## الأداة
`scripts/migration/run.mjs` (+ `lib/dump.mjs`):
- **dry-run افتراضي**؛ `--apply` صريح؛ `--step <اسم>` لخطوة واحدة.
- idempotent: مفاتيح طبيعية (sku `LEG-{id}`، orderNumber `SY-{legacyId}`، هاتف normalized، email) — إعادة التشغيل لا تكرر شيئاً (ثبت عملياً عبر عدة إعادات تشغيل).
- لا أسرار في الكود؛ نسخة احتياطية `pg_dump` تلقائية قبل الحذف في `scripts/migration/backups/` (git-ignored).
- استبدال الـ demo: حذف مرتّب صريح لصفوف الشركة التجريبية فقط (لا TRUNCATE/DROP/migrate reset)؛ المدير superadmin + الأدوار العامة + RolePermissionDefaults + SystemSettings محفوظة.

## خطوات GitHub وCoolify (لما توافق)
1. branch جديد (مثلاً `migration/salah-plus`) يحتوي: `scripts/migration/**` (الكود + .gitignore) و`docs/migration/salah-plus/**` — PR، لا دفع مباشر على main.
2. **لا يُرفع أبداً**: ملف SQL القديم، `backups/`، `.credentials.local.json`، `idmap.json`، `migration-report.local.json`، `.env` — كلها مستثناة في `.gitignore` الخاص بالمجلد.
3. على إنتاج Coolify: نسخة احتياطية pg_dump → تشغيل `node scripts/migration/run.mjs` (dry-run مراجعة) ثم `--apply` **مرة واحدة يدوياً** — الأداة ليست جزءاً من deploy ولن تعمل تلقائياً.
